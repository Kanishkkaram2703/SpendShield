SpendShield — Intelligent Payment & Financial Awareness Platform
1. Basic Project Idea

SpendShield is a smart digital payment application.

Its main goal is not just to make payments.

The app will also tell the user:

How much balance is left after the payment.
How much money is going to be deducted in the future.
Which subscriptions are automatically deducting money.
What the user's spending pattern looks like.
Whether any unusual or suspicious spending is happening.

Simple concept:

Pay → See Balance → Understand Where Money Is Going → See Future Payments → Decide

2. What Is the Problem?

In normal payment apps, the user makes a payment:

Balance = ₹1,500

Payment = ₹500

Payment Successful

But the user does not immediately feel that:

Now I have only ₹1,000.
How many more payments are coming in the future?
Which subscriptions will automatically renew?

In SpendShield:

PAYMENT SUCCESSFUL

Paid: ₹500
Before Balance: ₹1,500
After Balance: ₹1,000

This means that after every payment, the user will clearly see the remaining balance.

This is SpendShield's first major feature.

4. If the User Selects YES

If the user says:

YES, I USE IT

Then:

SpendShield will close the current reminder.
It will not disturb the user.
It will remind the user again before the next billing cycle.

Simple:

YES
 ↓
Current reminder dismissed
 ↓
Check again at the next renewal
5. If the User Selects NO

If the user says:

NO, I DON'T

Then SpendShield will say:

Review the subscription.
Check auto-renewal.
If you are not using it, you can turn OFF auto-renewal.

Example:

Auto-renewal: ON
        ↓
User reviews subscription
        ↓
Auto-renewal: OFF
        ↓
Future simulated deductions stop

Important:

SpendShield will not cancel the subscription by itself.

The final decision will be made by the user.

6. Notification System

The user will have a setting:

Subscription Awareness

Upcoming payment alerts
ON

When ON:

Reminder 4–5 days before.

When OFF:

Do not send reminders.

System philosophy:

Detect → Warn → Ask → Suggest → User Decides

SpendShield will not silently make decisions on behalf of the user.

14. Recurring Payment Detection — Main ML Feature

This is where the actual Data Science will come in.

The system will not simply hard-code:

"StreamBox = Subscription"

Instead, it will identify the pattern from transaction history.

Example:

22 May → StreamBox → ₹299
21 Jun → StreamBox → ₹299
22 Jul → StreamBox → ₹299
21 Aug → StreamBox → ₹299

Python will analyze:

Merchant
Amount
Dates
Time interval
Frequency
Historical behavior

And output:

Merchant: StreamBox
Amount: ₹299
Frequency: Monthly
Confidence: 98%

This means:

The system itself detected the recurring payment.
